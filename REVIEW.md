# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72-74) | Health probe does not verify MongoDB connectivity; returns static `{"status": "ok"}` unconditionally. | Stop MongoDB service; `GET /health` continues returning HTTP 200 instead of HTTP 503. | Added `client.admin.command("ping")` within a `try/except` block, raising `HTTPException(503, "Database unavailable")` on failure. |
| 2 | `list_employees` (line 93) | Off-by-one pagination bug. `skip = page * page_size` skips the first page entirely when `page=1` (`skip = 1 * 20 = 20`). | `GET /employees?page=1&page_size=20` returns items 21–40 instead of items 1–20. Page 1 can never be retrieved. | Changed skip calculation to `skip = (page - 1) * page_size`. |
| 3 | `list_employees` (line 94) | `total` count ignores query filters. `total = db.employees.count_documents({})` passes empty filter `{}`. | `GET /employees?department=Engineering` returns the total count of all employees across all departments rather than the count in Engineering. | Passed the active query filter to count: `total = db.employees.count_documents(q)`. |
| 4 | `list_employees` (line 95) | Missing sorting by `emp_code` ascending. `db.employees.find(q, {"_id": 0})` omitted `.sort()`. | Employee list is returned in non-deterministic MongoDB natural insertion order. | Added `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 5 | `list_attendance` (lines 144-147) | Unbounded in-memory loading and sorting of attendance records. Fetches entire collection via `list(db.attendance_logs.find(q))` and sorts in Python. | At 100k+ attendance records, this causes memory exhaustion, high GC pauses, and extreme request latency. | Delegated sorting, skipping, and limiting directly to MongoDB: `db.attendance_logs.find(q).sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |
| 6 | `list_attendance` (line 145) | Missing secondary sort key. Starter only sorted by `date` descending, omitting `emp_code` ascending. | Multiple attendance records with the same date appear in arbitrary, unstable order. | Added compound sort order `[("date", -1), ("emp_code", 1)]` to the database query. |
| 7 | `list_attendance` (lines 136-141) | Missing date range validation when `date_from > date_to`. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` executes an inverted query returning empty results instead of returning HTTP 422. | Added validation `if date_from and date_to and date_from > date_to: raise HTTPException(422)`. |
| 8 | `create_employee` (lines 79-83) | Concurrency race condition due to application-level check-then-insert and missing unique index. | Simultaneous concurrent POST requests with the same `emp_code` both pass `find_one` and create duplicate employees. | Created a unique index on `emp_code` at startup and catch pymongo `DuplicateKeyError` to return HTTP 409 Conflict. |
| 9 | `create_employee` (lines 81-85) | Missing schema validations and improper datetime serialization. `created_at` stored as local naive datetime and returned as unformatted datetime object instead of epoch ms. | Client sending invalid `emp_code` format or equal `shift_start`/`shift_end` is accepted. Response returns unformatted datetime rather than integer epoch ms. | Created Pydantic `EmployeeCreate` model with regex, shift inequality validation, stored UTC datetimes, and returned integer epoch milliseconds. |
| 10 | `punch_in` (line 101) | Unhandled HTTP 500 error when `emp_code` does not exist. `emp` is `None`; accessing `emp["shift_start"]` raises `TypeError`. | `POST /attendance/punch-in` with an unknown employee returns HTTP 500 Internal Server Error instead of HTTP 404. | Added `if not emp: raise HTTPException(404, "Employee not found")`. |
| 11 | `punch_in` (lines 104-118) | Concurrency race condition allowing duplicate daily punch-in logs. Check-then-insert without database unique constraint. | Two concurrent punch-in requests for the same employee and date both insert records instead of exactly one 201 and one 409. | Created a compound unique index on `("emp_code", "date")` at startup and catch `DuplicateKeyError` to return HTTP 409 Conflict. |
| 12 | `compute_late_minutes` (lines 36-37) | Grace period threshold flaw (R2). Evaluates `minutes = int((punch_in - start).total_seconds() / 60)` then checks `minutes > 10`. | For shift 09:30, punch-in at 09:40:01 has 601s elapsed (> 10:00). Floor division gives 10. `10 > 10` returns 0 instead of 10! | Checked `elapsed_seconds > 600` strictly, returning `elapsed_seconds // 60` if true, otherwise 0. |
| 13 | `compute_late_minutes` (line 35) | Timezone mismatch and missing instant truncation. Replaces hour/minute directly on `punch_in` without converting UTC to IST (+05:30). | Punch-in at 04:35 UTC (10:05 IST) was compared against 09:30 UTC instead of 09:30 IST. Instants were not truncated to whole seconds per R1. | Truncated instants to whole seconds and converted UTC datetimes to IST before calculating elapsed shift time. |
| 14 | `compute_overtime` (line 47) | Missing 30-minute minimum threshold requirement (R3). | A punch-out 5 minutes after shift end returned 5 overtime minutes instead of 0. | Enforced R3: return overtime minutes only if `>= 30`, otherwise return 0. |
| 15 | `compute_overtime` (line 46) | Shift end date calculation breaks for overnight shifts. Constructed shift end on `date_str`, ignoring that overnight shifts end on the next day. | For shift 22:00–06:00, punching out at 06:40 IST next day computed overtime from previous day 06:00, yielding 1480 minutes instead of 40 minutes. | Checked `if shift_end <= shift_start`, adding 1 day to attendance date for the shift end datetime in IST. |
| 16 | `compute_work_hours` (line 41) | Python built-in `round()` uses Banker's Rounding (round-half-to-even) instead of Decimal Half-Up (R4). | `round(2.675, 2)` produces `2.67` instead of `2.68` (half-up). | Replaced with `decimal.Decimal` and `ROUND_HALF_UP` quantization. |
| 17 | `punch_in` (lines 102-103) | Attendance date calculation used local OS system timezone instead of IST and ignored overnight shift attribution (R1). | Running on UTC/US servers assigns the wrong calendar date. Overnight punches before `shift_end` were not assigned to previous shift start date. | Explicitly converted instants to IST and assigned punch-ins before `shift_end` on overnight shifts to the previous calendar day. |
| 18 | `punch_in` / `list_attendance` (lines 119, 149) | Exposing internal MongoDB `_id` as `id` and returning unformatted datetimes. | Responses failed OpenAPI `AttendanceRecord` schema validation (`id` is not in schema; punch times returned as ISO strings instead of epoch ms). | Omitted `_id`/`id` and converted all instant fields (`punch_in`, `punch_out`, `history.at`, `changes.from`, `changes.to`) to integer epoch milliseconds. |

## Examined and Decided Was NOT a Defect

1. **`load_dotenv()` at startup without `override=True`**: Standard behavior in `python-dotenv` ensures existing environment variables set in the runtime/OS take precedence over `.env` defaults, satisfying the requirement that real environment variables must win.
2. **`status` default in `PunchInRequest` being `"PRESENT"`**: This matches the default specified in `openapi.yaml` for `PunchInRequest`.
3. **`emp_code` format string and immutability**: `emp_code` is explicitly defined in `DATA_MODEL.md` as the business identifier assigned by HR rather than an internal database identifier.
